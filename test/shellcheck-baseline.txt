# test/shellcheck-baseline.txt
#
# Known, accepted shellcheck findings. One `CODE<space>PATH` pair per line;
# `#` starts a comment. A finding listed here is reported as "known" and does not
# fail the build; anything NOT listed here does.
#
# This is how an exception gets annotated instead of the whole check being
# lowered to shut it up. Two rules for adding a line:
#
#   1. Say why, on the line.
#   2. If the reason is "someone is going to fix this", name who, so the entry
#      reads as a debt and not as a decision.
#
# The path field is a glob (`*` and `?`), so an entry keeps matching when a file
# is moved rather than going stale and failing the build for a finding that was
# already accepted.
#
# Entries scoped to a real path are reported as stale at the end of the lint run
# (a notice, not a failure) once nothing matches them — delete them when you see
# that. Entries scoped to bare `*` are policy and are never reported as stale.

# --- Policy: inherent to a dotfiles repo -----------------------------------
# Shell rc files exist to source machine-local files that are not in the repo
# and cannot be in the repo. shellcheck can never follow them, and it is not a
# defect that it can't.
